Home screen audit → redesign

Stop scrolling shelves.
Start continuing, finding, tidying.

Findly's core jobs are capture → re-find → resume → organise → check health. The current Home shows Recently Added / Recent / Most Used / Pinned / Favorites as five identical horizontal shelves, pushes type + tag filters to the bottom, and has no search entry (search lives in another tab). Each concept below fixes that with native iOS patterns only — large title, search field, inset grouped lists, segmented control, grids — and keeps the exact same bottom Tab Bar (Home · Tags · Files · Insights · Search) plus the blue + FAB.

🔍 What's wrong today HomeView.swift

  • 5 shelves, same ItemCardView grid — nothing looks more important.
  • Recently Added vs Recent (added vs opened) is confusing.
  • Type chips + tag pills at the bottom, far from Search tab logic.
  • No resume of last file, no sync/storage signal, weak empty state.

🧭 Principles used

  • Native first: NavigationStack, .searchable, inset grouped List, Picker(.segmented).
  • One primary job per screen — hero element answers "why am I here?".
  • Tab Bar never changes — Home earns its place, doesn't duplicate Files/Search/Insights.
  • Reuse, don't rebuild: same ViewModel queries + ItemCardView(.row).

⭐ Recommendation

Ship 01 Continue First. It has the fastest path to the #1 job (resume last file), keeps Pinned + Recent in native rows, and surfaces sync issues inline. Add 04 Timeline's segmented filter as a phase-2 iteration. Use 02 only if vault > 500 items / search dominates.
